整体优化策略

5个维度都要覆盖，但以什么节奏推进？

A

深度优先 —— "打磨现有"

先把现有功能做到生产级质量：冲突确认 UI 补全、privacy_level 落地、流式输出、测试覆盖提升、数据生命周期管理。

好处

  • 系统更稳定可靠
  • 用户直接受益

不足

  • 新功能较少
  • Skill/MCP 架构延后
B

广度优先 —— "扩展边疆"

优先增加新能力：Skill 插件系统、MCP 协议化、智能日程分析、多用户支持、对话历史搜索。

好处

  • 功能更丰富
  • 项目亮点更多

不足

  • 可能引入不稳定
  • 测试债累积
C

主题驱动 —— "按支柱推进"

按项目三大支柱分阶段推进。每个阶段覆盖一个支柱及其相关维度：
Phase 1: Skill 系统升级（插件化 + MCP）
Phase 2: 本地 LLM 体验增强（流式 + Agent 透明化）
Phase 3: 隐私保护深化（privacy_level + 数据生命周期）
贯穿: UX 打磨 + 架构债修复穿插在所有阶段

好处

  • 每个阶段有清晰主题
  • 阶段性交付

不足

  • 跨阶段依赖需仔细管理
