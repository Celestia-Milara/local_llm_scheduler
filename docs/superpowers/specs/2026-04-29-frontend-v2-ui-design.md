# v2.0 前端交互与界面改造设计

**目标**
在保留自然语言对话能力的前提下，提供按日期管理日程的手动编辑体验，支持按天筛选、内联编辑、冲突建议提示，并与现有后端接口对齐。

**范围**
- 前端页面结构调整：左侧月历 + 对话区域，右侧当天事件列表。
- 日历日期选择与事件标记。
- 事件卡片内联编辑与保存。
- 冲突建议的弹窗提示。
- 不改动后端接口语义，仅按现有 API 调用。

## 一、布局与信息结构

- 左侧上半：月视图日历，可切换月份。
- 左侧下半：对话区，展示与模型的历史对话记录及输入框。
- 右侧：所选日期的事件列表，默认显示“今天”。
- 月历上有事件的日期显示小点标记。

## 二、交互与状态

- 点击月历日期后：右侧列表展示该日期事件。
- 事件卡片支持内联编辑：点击“编辑”进入编辑态。
- 保存方式：显式“保存/取消”按钮，回车可触发保存。
- 删除方式：保留现有删除按钮。
- 冲突建议：当模型返回冲突与替代时段时，用弹窗提示展示。

## 三、数据与请求流

- 日历事件标记：加载月内事件后，由前端统计当天是否有事件并显示小点。
- 当天列表：调用 `/schedules?start=YYYY-MM-DD&end=YYYY-MM-DD` 获取。
- 内联编辑保存：调用 `PUT /schedules/{id}`。
- 删除事件：调用 `DELETE /schedules/{id}`。
- 对话区：继续调用 `/chat`。

## 四、视觉与交互细节

- 日历选中日期高亮，今日日期有特殊标识。
- 编辑态输入框与按钮布局紧凑，不破坏卡片信息结构。
- 冲突弹窗：展示替代时段，可点击“采用此时段”回填编辑表单，或提示用户继续对话确认。

## 错误与边界处理

- 月历请求失败时：显示轻量错误提示，不影响聊天区域。
- 事件更新失败时：弹出错误提示，保留编辑内容供重试。
- 冲突弹窗仅在模型返回包含建议时段时触发。

## 测试要点

- 选择日期后列表切换正确。
- 内联编辑保存成功后列表刷新。
- 回车触发保存且不重复提交。
- 删除后列表刷新。
- 冲突弹窗显示且可关闭。
